Codex Account Desk 1.12.0 — 소스

빌드: .NET 8 SDK, Windows x64
명령:
  dotnet publish CodexAccountDesk.csproj -c Release -r win-x64 --self-contained true -p:UseSharedCompilation=false -o publish

위 명령으로 생성된 publish 폴더 전체를 배포합니다.
이 소스는 NuGet 외부 패키지를 추가로 사용하지 않습니다.

내부 검증:
  publish\CodexAccountDesk.exe --self-test --verify-readonly "C:\absolute\path\self-tests.json"

실제 현재 계정 조회 및 WPF 렌더링 검증:
  publish\CodexAccountDesk.exe --data-dir "C:\absolute\path\isolated-state" --verify-readonly "C:\absolute\path\usage-report.json" --preview "C:\absolute\path\preview.png"

영어 검증 인스턴스:
  publish\CodexAccountDesk.exe --data-dir "C:\absolute\path\isolated-state-en" --language en --verify-readonly "C:\absolute\path\usage-report-en.json" --preview "C:\absolute\path\preview-en.png"
--language ko 또는 en은 해당 저장소의 언어 설정을 저장합니다.
언어 옵션을 생략한 별도 실행에서도 저장된 설정이 복원됩니다.

실제 계정을 사용하지 않는 추이/예측 화면 검증:
  publish\CodexAccountDesk.exe --preview-trends "C:\absolute\path\trend-previews"
소진 우선, 리셋 우선, 기록 수집 중 상태를 한국어/영어와 다크/라이트로 렌더링합니다.
이 화면의 데이터는 검증용 예시이며 실제 계정 기록에 추가하지 않습니다.

물탱크 상태 화면 검증:
  publish\CodexAccountDesk.exe --preview-tanks "C:\absolute\path\tank-previews"
0/9/52/100% 잔량, 정보 없음, 복수 한도 구간을 두 언어/테마로 렌더링합니다.
실제 조회 검증은 추이 버튼을 눌러 메인 화면이 활성 상태로 유지되는지 확인하고 좁은 창도 렌더링합니다.

조회 검증은 추가 계정 로그인을 실행하거나 Codex 앱을 종료하지 않습니다.
Codex에서 토큰 자동 갱신이 필요한 경우 기존 로그인 파일에 갱신된 정보를 동기화할 수 있습니다.
보고서의 sourceAuthUnchanged는 해당 실행에서 실제 파일이 유지됐는지 나타내며 항상 true라고 가정하지 않습니다.
검증용 state 폴더에는 암호화된 계정 등록 정보가 저장되므로 소스/배포 ZIP에 포함하지 않습니다.

역할:
- Models.cs: 인증 캐시 식별, 서버 응답 모델, 한국 시간 표시
- RefreshCoordinator.cs: 계정별 중복 조회 합치기와 새 로그인 조회 우선 처리
- Burn0Theme.cs / Burn0Tokens.css / Burn0Icons.json: Burn0 공용 토큰과 아이콘의 WPF 변환
- Localization.cs / Strings.ko.json / Strings.en.json: 한국어·영어 문구, 숫자·시간 형식과 즉시 전환
- UsageAnalysis.cs: 실측 기록 수집/보관, 구간 분리, 최근 평균 속도로 소진/리셋 순서 계산
- UsageOutlook.cs / UsageTrendChart.cs: 예측 요약, 실측 그래프, 마우스 조회값, 미래 이벤트 시간축
- TrendDiagnostics.cs: 실제 계정에 영향을 주지 않는 예측 화면 검증
- TankGaugeSurface.cs / AccountTankCard.cs: 전체 배경 수위, 큰 잔여 숫자, 한도 선택과 소진/리셋 요약
- AccountCardHeader.cs: 카드 크기에 따른 이름/메타데이터/조작 버튼 재배치
- AccountDetailWindow.cs: 메인 화면을 막지 않는 추이·크레딧 상세 창
- TankDiagnostics.cs: 0%, 만수위, 낮은 잔량, 정보 없음, 여러 한도 구간 화면 검증
- Storage.cs: DPAPI 저장, UTF-8 원자 교체, 임시 폴더 경로 검증
- CodexRpc.cs / OwnedProcessJob.cs: 공식 app-server 통신과 소유 프로세스 종료 관리
- Runtime.cs: 현재 설치 검색, 조회용 임시 CODEX_HOME, 데스크톱 실행 확인
- AccountService.cs: 계정 등록, 조회, 인증 갱신 보관, 데스크톱 종료 후 계정 적용
- MainWindow.cs: WPF 화면, 트레이 메뉴, 갱신 및 전환 예약
- Program.cs: 단일 인스턴스, 실행 옵션
- Diagnostics.cs: 로컬 검증과 비밀 정보 없는 조회 보고서

설계 경계:
- usage RPC에 공식 인증 캐시를 사용하며 모델 요청이나 별도 추론을 실행하지 않습니다.
- 계정 구분에는 사용자 subject와 workspace/account ID를 함께 사용합니다.
- 새 로그인은 현재 계정과 같아도 명시 적용 전까지 활성 로그인 파일을 교체하지 않습니다.
- 토큰 갱신 결과는 후속 사용량 조회가 실패하거나 취소되더라도 유실하지 않도록 보관합니다.
- 조회/로그인은 전역 잠금으로 직렬화하지 않습니다. 계정별 조회를 합치고 최대 3개의 조회를 동시에 실행합니다.
- 저장소 변경만 짧은 동기 구간으로 묶으며 인증이 바뀌거나 계정이 제거되면 이전 조회의 결과를 반영하지 않습니다.
- 계정 등록 후 반환하는 AccountRegistration.ImmediateRefresh는 이미 시작된 해당 계정 조회입니다. UI는 로그인 입력 상태를 먼저 해제하고 이 조회 완료를 기다립니다.
- 프로그램 종료 시에는 대기 중이거나 나중에 예약되는 조회까지 취소합니다.
- 전환 전에 모든 해당 데스크톱 프로세스의 종료와 활성 로그인 파일의 변경 여부를 다시 확인합니다.
- Windows 앱을 강제 종료하거나 공개되지 않은 내부 IPC로 계정을 주입하지 않습니다.
- file 저장 방식에서 동작하며 keyring/auto/ephemeral 설정은 자동으로 변경하지 않습니다.
- 사용자의 Codex 설정에서 지정한 로그인 방식과 워크스페이스 요구 조건을 확인합니다.
- DPAPI 저장소를 다른 Windows 사용자에게 옮기면 복호화할 수 없습니다.
- 언어 설정은 기존 DPAPI 저장소에 함께 보관합니다. 기존 저장소에는 한국어가 기본 적용됩니다.
- 화면 문구는 언어 카탈로그에서 조회하며 사용자가 지정한 계정 이름과 서버에서 받은 값은 번역하지 않습니다.
- 언어 변경 시 화면과 트레이를 다시 구성하되 조회 서비스와 진행 중인 비동기 작업은 유지합니다.
- 한국어·영어 JSON은 WithCulture=false와 명시적인 LogicalName으로 주 실행 어셈블리에 포함합니다.
- 실측 기록은 조회 성공 및 인증 버전 검증 후에만 추가하며 실패/취소 시 허위 관측을 만들지 않습니다.
- 기록은 계정, 한도 bucket ID, primary/secondary, 기간 길이를 구분합니다. 리셋 변경 또는 사용량 감소는 새 예측 구간을 만듭니다.
- 최대 30일을 보관하며 최근 2일은 1분, 이전 기록은 15분 단위로 압축합니다. 각 단위의 실제 마지막 조회값을 유지하고 구간 경계를 보존합니다.
- 예측은 최근 24시간의 완전히 관측된 10분 증가 구간을 사용합니다. 구간 3개와 총 0.1%p 이상 증가가 필요하며, 중앙값 초기화와 보정 폭을 제한한 EWMA를 사용합니다. 정확한 파라미터와 조건은 예측공식.md에 기록했습니다.
- 마지막 조회가 15분 이상 오래됐거나 관측 사이에 15분을 넘는 공백이 있으면 그 구간으로 소진 시각을 예측하지 않습니다.
- 예측 소진 시각은 마지막 실측 시각부터 계산합니다. 현재 시각으로 기준점을 밀어 소진 시간을 늦추지 않습니다.
- 리셋이 먼저면 리셋 직전 예상 사용률을 표시하고, 더 늦은 소진 시각은 '리셋이 없을 경우'로 명시합니다.
- 예상 시각이 지났거나 리셋 시각이 도달해도 실제 조회 사용률을 변경하지 않습니다.
- 프로그램이 종료된 동안의 기록과 설치 이전 기록을 재구성하지 않습니다. 이전 버전의 마지막 실측 한 점만 이어서 사용합니다.
- 물 높이는 남은 사용률이며 중앙 숫자도 같은 값입니다. 값이 없으면 수위와 퍼센트를 만들지 않습니다.
- 카드 기본 값은 가장 적게 남은 한도이며, 다른 한도는 카드를 누르지 않고 해당 기간 값 버튼으로 선택합니다.
- 카드의 그래프는 modeless 상세 창으로 옮겨 메인 조회/전환 버튼을 계속 사용할 수 있게 했습니다.
- 창 크기와 스크롤바로 viewport 너비가 달라지면 카드 너비를 다시 계산합니다.
- 1.5부터 메인 계정 영역은 스크롤 없는 UniformGrid로 가로·세로 공간을 함께 분배합니다. 4개 계정은 작은 창에서도 2x2를 유지합니다.
- 전환/더보기 버튼은 모든 크기에서 카드 오른쪽 위에 유지하고 실제 숫자 영역의 높이로 글자 크기를 계산합니다. 최소 창은 500x360, 기본 창은 600x400입니다.
- 작은 창에서 한도 선택 버튼이 축약되면 중앙 숫자를 눌러 다른 한도를 선택할 수 있습니다.

- Windows 11의 최대화/스냅 모서리 처리는 운영체제 정책을 따릅니다. 이전 Windows에서는 WindowChrome의 8px 라운드를 사용합니다.
- WPF RenderTargetBitmap 미리보기에는 운영체제가 합성하는 창 모서리가 포함되지 않습니다. HWND의 DWM 속성/영역 상태를 별도로 확인합니다.

- 조회 검증 모드에서는 실제 언어 메뉴 선택과 테마 버튼을 3회 순환(총 12회 변경)하며 이 경로를 확인합니다. 테스트 실패는 보고서 appearanceSwitch.passed=false 및 스택으로 기록하며 일반 실행 동작을 우회하지 않습니다.
- 1.9은 모든 계정 카드의 기존 소진/리셋 요약 두 줄 오른쪽에 요금제와 초기화권을 항상 표시합니다. 최소 창에서도 카드 높이와 잔량 숫자 공간을 유지합니다.
- 초기화권은 UsageSnapshot.AvailableResets를 표시하며 0과 null을 구분합니다. null은 '—'이고 숫자 0으로 추정하지 않습니다. planType의 prolite는 'Pro Lite'로 표시합니다.
- ProbeBounds에 요금제/초기화권 가시성·경계 검사를 추가했습니다. 실제 값과 표시 값을 함께 확인하며 상태 예시 렌더링도 두 언어·두 테마의 0/양수/미제공 수량을 포함합니다.
- 1.10은 ID token의 https://api.openai.com/auth 안에 있는 chatgpt_subscription_active_until 및 chatgpt_subscription_last_checked를 파싱합니다. JWT exp는 구독 종료일로 사용하지 않습니다.
